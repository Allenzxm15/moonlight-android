包名仍是 `com.limelight.noirdebug`。使用同一本地签名，可覆盖此前 fix1 试用包。
本版只提交源码、测试和使用说明；APK、本地构建工具和签名密钥不进入 Git 仓库。

## 如何使用

1. 覆盖安装新 APK，打开 `Artemis L/R`。
2. 保持“设置 → 特殊按键布局 → 屏幕显示虚拟按键”开启。
3. 串流后点特殊按键的设置按钮，进入启用/禁用模式。
   启用 `L/R`、`LCtrl`、`LShift`、`1000`、`1000000`。
   若没有看到，可用“添加按键”选择；这些按钮也会加入默认布局。
4. 按需调整位置和大小，继续点设置按钮直到保存退出。

| 按钮 | 效果 |
| --- | --- |
| `L/R`（运行时显示 `L` 或 `R`） | `L`：触屏单击模拟左键；点一下变成高亮的 `R`：触屏单击模拟右键；再点恢复。 |
| `LCtrl` | 点亮表示按住**左 Ctrl**，再点熄灭表示松开。 |
| `LShift` | 点亮表示按住**左 Shift**，再点熄灭表示松开。 |
| `1000` | 向当前输入焦点输入 `1000`，不清空已有内容、不自动回车。 |
| `1000000` | 向当前输入焦点输入 `1000000`，不清空已有内容、不自动回车。 |

`LCtrl` 和 `LShift` 可同时开启，和左右鼠标键切换组合使用。
它们是独立锁定按钮，不依赖原有“粘滞修饰键”设置。
锁定相当于真正按住键盘修饰键，因此也会影响其他键盘操作，不只影响鼠标。

## 首次连接的处理

启用且显示 `L/R` 快捷按钮时，会在接收触屏点击前将多点触控、触摸板或禁用模式
转为左键单点触控，避免“按钮没亮，但实际仍在发送原生触摸事件”。
若已保存左键或右键单点模式，则保留该选择；自动转换不改写保存的鼠标模式设置。
不启用 `L/R`、仅远程输入模式或外接屏场景不做此自动转换。
从菜单主动选择其他模式后，按钮显示 `L/R`，不再把它伪装成左键 `L`。

## 数字输入与防卡键

- 新按钮在手指抬起时触发一次，不长按连发，不滑入相邻按键。
- 滑出按钮范围、取消手势、隐藏/编辑/重建布局时，未完成的点击不会再触发。
- 数字通过逐个数字键的按下/松开发送，按下和间隔各约 40 毫秒。
  每次 `1000000` 约需 0.6 秒；快速多次点按按顺序排队，队列有长度上限。
- 输入数字时会暂时释放本次新增的 Ctrl/Shift 锁定，完成后恢复，避免生成快捷键或标点。
- 如果其他键盘或旧的虚拟修饰键还按着 Ctrl/Shift/Alt/Win，数字按钮会提示先松开，
  不会擅自释放这些键。建议使用新增的 `LCtrl`、`LShift`。
- 数字尚未输完时触碰串流画面或按下普通键，会中止剩余数字，释放当前数字键，
  并先恢复锁定修饰键，使随后的点击保持 Ctrl/Shift 效果。
- 隐藏按钮、进入编辑、应用失焦/进入后台或结束连接时，释放本次新增的锁定键并取消数字队列。
  重新连接不会自动按住 Ctrl/Shift。网络已断开时无法保证松键包送达，主机仍需处理断线输入清理。

## 验证

已完成本地 Android APK 构建及 14 项纯 Java/JUnit 输入状态测试。
测试覆盖初始鼠标模式选择、左右修饰键代码、组合锁定、数字按下/松开配对、
连续排队、暂时释放和恢复、输入中断、重复清理以及非法/超长输入。
2026-09-17，用户试用 v2 后反馈各项功能使用正常。
这是用户的实机使用反馈，不代表下面的边界场景已有逐项测试记录。

真机检查建议：

1. 断开后重新连接，不碰 `L/R`，直接点击桌面图标/游戏界面，确认左键生效。
2. 切换 `L` / `R`，确认行为与文字、高亮一致。
3. 在文件管理器中测试 `LCtrl` 多选、`LShift` 范围选择，再各点一次确认解除。
4. 在空白记事本输入框和游戏数量输入框分别测试两个数字按钮，不应带回车或漏掉零。
5. 开启 `LCtrl` + `LShift` 后输入数字，确认数字正确，结束后点击仍带两个修饰键。
6. 稍微滑出按钮再抬手、长按按钮、快速连点，检查无 I/J 等额外字符，无持续输入。
7. 数字输入中切后台或隐藏按钮，再回来，确认没有继续输入，Ctrl/Shift 已熄灭。

主要代码：`TouchShortcutState.java` 管理会话内状态及数字队列；`Game.java` 接入鼠标模式、
键盘修饰标记和生命周期；`KeyBoardController*` / `KeyBoardDigitalButton` 接入布局及点击交互；
`keyboard.json` 提供五个快捷按钮条目。
